# 请求脱敏

在插件中心启用插件后，从主导航打开「请求脱敏」。选择已有路由，添加字面文本或正则规则，再保存绑定。每条路由独立保存规则，可在本页解绑；未绑定的路由不应用规则。

通过配置 API 填写同样的规则时，绑定选项 `rules` 是一个数组，例如：

```json
[
  { "type": "literal", "pattern": "内部项目代号" },
  { "type": "regex", "pattern": "acct-[0-9]+", "replacement": "[ACCOUNT]" }
]
```

- `literal` 区分大小写，按字面子串匹配。`regex` 接受 RE2 表达式，不带 `/…/` 分隔符；可用 `(?i)` 忽略大小写，不支持反向引用和环视。
- 按数组顺序处理每条规则，替换解析后 JSON 字符串值中的所有匹配，不匹配键、数字、布尔值和 `null`。正文会重新序列化。省略 `replacement` 使用 `[REDACTED]`；空字符串表示删除匹配内容。`$1` 等按字面输出，不展开捕获组。后续规则会处理前一条规则的替换结果。
- 必须填写 1–32 条规则。`pattern` 必须非空，`pattern` 和 `replacement` 均不得超过 4096 个 UTF-16 代码单元。处理中每个请求累计新增超过 1 Mi 个 UTF-16 代码单元时拒绝转发。已绑定的路由如果规则无效，拒绝处理有正文的方法；无法解析为 JSON 的正文也不会原样转发。

插件只改写经过该请求钩子的出站 JSON，不清理已记录的原始请求、请求头、响应或 WebSocket 直通消息。不要把规则中的字面值当成加密凭据存放；它们是普通插件配置。若路由还会在后续阶段生成或写入文本，确保这些文本也在实际出站前经过脱敏。

## 脱敏统计

页面上的统计汇总所有工作进程，不随选中的路由切换。显示已完成的脱敏规则执行次数、其中发生替换的次数，以及实际改变文本的替换总数。多次执行分别计数；已处理不代表上游收到请求或处理成功。

统计异步汇总到访问数据库，短时可能滞后。不保存正文、命中片段或规则内容；进程异常退出或上报失败时，计数可能少于实际值，不用于审计。读取接口为 `GET /api/plugins/request-body-redaction/control/stats`，需要 `logs.read` 权限。
