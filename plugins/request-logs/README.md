# 请求日志

Bungee 随发行目录提供 `request-logs`，首次使用时默认启用。管理员可在插件中心停用或重新启用。插件启用时贡献「请求日志」菜单和页面，正文采集选项位于插件管理的「请求日志 → 设置」。停用后移除页面和设置入口，已有日志仍可通过 `/api/logs` 按原权限查询和导出。

默认记录 HTTP 方法、路径、状态码、耗时和传输结果。开启插件设置的正文记录后，默认解析 `application/json`、`+json` 和 `text/plain`。媒体类型未匹配、解析失败或超限时保留访问元数据。留空保存时使用 64 KiB 和 1 天。单条正文上限可设为界面能精确表示的整数字节数。正文分块写入磁盘，单条上限与 Worker 的日志内存预算独立。磁盘写入跟不上或采集失败时，跳过该份正文并保留访问记录。

插件根据 HTTP 响应或 WebSocket 双向消息自动识别应用协议。识别独立于正文记录设置，开启正文记录后才保存识别到的 SSE 事件。已登记的操作缺少可确认的终态时标记观察不完整。WebSocket 每次已识别的客户端业务请求产生一条记录，握手、空闲连接与插件内部调用不参与请求日志。

- **Responses** 支持 HTTP JSON 和 SSE，以及直通和托管 WebSocket。直通连接通过客户端请求和带响应 ID 的上游打开事件确认归属，时间从客户端首帧计算。托管连接使用网关在客户端消息边界分配的关联 ID。开启正文记录后，在每次操作详情的「原始请求」和「响应」中查看客户端 JSON 请求和按发送顺序保存的响应消息数组。消息归属有歧义、连接在终态前关闭或正文超限时，相应正文缺失并记录原因。客户端收到确认的成功终态后直接断开，该次请求仍按成功结算。
- **Gemini** 支持 `generateContent` JSON、`streamGenerateContent` SSE 和 Live `bidiGenerateContent` WebSocket。Live 通过 setup 握手确认协议，按生成轮次记录结果，支持服务端二进制 JSON。
- 普通 SSE 保留 HTTP 访问和传输结果。未被观察器认领的普通 WebSocket 不产生请求日志。

内置协议识别器位于 [server/protocols](server/protocols)，通过同一个注册表接入正文解析和应用观察。第三方扩展参见 [SDK](../../docs/reference/plugin-api.md#请求日志扩展)。

历史 WS 连接行和内部尝试保留在存储中，可按原记录 ID 查询。默认请求列表、导出和统计以客户端请求为单位。

SQLite、JSONL 与正文保留沿用现有日志设置。默认以访问数据库所在目录保存正文和请求头。设置 `BUNGEE_BODY_LOG_DIR` 或 `BUNGEE_HEADER_LOG_DIR` 可指定相应目录。
