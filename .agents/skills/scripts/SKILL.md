# 项目脚本

## 确定用途和授权

- 读取项目 AGENTS.md，检查任务是否授权新增永久工具。Skill 本身不授权发布、部署、修改外部服务或清理数据。
- 优先复用现有入口。仅当持续维护任务需要重复执行或需要确定性自动化时新增正式工具。
- 一次性诊断、任务执行记录和个人环境工具放项目外临时目录；不因脚本来自 Agent 或使用临时输出目录就判定其无价值。

## 选择归属

| 用途 | 归属 |
| --- | --- |
| 构建、打包、资源生成 | 项目构建工具目录 |
| 版本同步、发布、产物上传 | 项目发布工具目录 |
| 容器入口、健康检查 | 项目运行工具目录 |
| 可重复静态检查 | 项目检查工具目录 |
| 有断言的功能或浏览器验收 | 测试目录 |
| 可重复性能测量 | 基准目录 |
| 仅服务单个包的工具或测试 | 该包内 |

目录遵循项目约定，不为不存在的用途建立空目录。可重复测试的运行产物遵循项目测试目录约定，不纳入版本管理。

## 编写执行契约

- 完整阅读即将修改的脚本及其调用方。明确入口、输入、输出、所需依赖、退出码、生成产物和副作用。
- 命令参数或环境变量承载可变配置；路径相对脚本或明确的项目根解析，不依赖个人工作目录、服务器地址或会话任务编号。
- 测试服务地址和端口允许通过参数配置或由测试分配；正式运行默认端口由产品契约决定，不机械删除。
- 失败返回非零退出码，不吞错误或输出虚假的成功结果；异步工作必须等待完成。
- 临时服务和文件明确所有权并在退出时清理，不删除非本次创建的资源；日志不输出凭据。
- 新增工具的用途和入口写进现有开发文档或入口帮助，不另建实施记录。

## 移动、删除和交付

- 删除前确认持续用途、替代入口和调用关系；没有引用只是证据之一。
- 移动时核对相对 import、工作目录、项目根、测试夹具、生成位置、文件权限和执行入口。
- 同步更新 package 命令、CI、Docker、发布配置、文档及其他脚本引用，不保留旧路径转发器。
- 按授权执行相关格式、链接、入口及行为检查；发布和生产操作必须遵循项目授权。
- 在会话中报告处置理由、实际验证和未验证事项，不新增脚本清理报告或交付记录。

## 测试维护

- 按主要验证的责任归属：包和插件放自己的 `tests/`，工具放 `scripts/tests/`，跨模块流程放根 `tests/`。使用 `unit/`、`integration/`、`browser/` 按层级区分，再按实际子系统分组；只创建需要的目录。
- 入口命名 `<对象或行为>.test.ts`，采用连字符，不重复 `.unit`、`.integration`、`.browser` 后缀，不使用任务编号或含义模糊的 final/new/v2。单个文件围绕相关行为，不限制行数。
- `unit/` 不启动数据库、服务、子进程或浏览器；真实本地资源放 `integration/`，真实页面和组件交互放 `browser/`。需要外部服务、凭据或人工准备的验收放根 `tests/manual/`，不使用自动发现后缀。
- 新增前找既有覆盖。保留公开行为、独立接线价值和必要异常路径，参数化重复输入；删除时明确失效原因或保留测试中的覆盖去向，不以文件名、关键词、长度或数量决定。
- 禁止截取源码函数执行或复制生产算法计算预期值。纯逻辑正常导入；绑定、异步刷新、弹窗、快捷键和主题通过实际组件验证。架构约束检查实际语法和作用域，不锁定缩进、注释、图标路径等无关细节，不扩大豁免。
- 创建、等待、清理、fake 和 stub 放 `helpers/`；被系统加载的输入、示例插件、故障 worker、组件宿主放 `fixtures/`。导入辅助代码不得启动资源。先局部使用，确有跨模块复用再放根辅助目录；辅助代码自身的测试另放对应层级。
- 小型输入就地声明；重复使用或必须保留字节的数据才保存为夹具。入口之间不得相互导入，生产代码不得依赖测试。快照放对应目录 `__snapshots__/`；截图、日志、数据库、性能结果放项目外，不提交。保留夹具必要来源和许可证，不新增会话式 README。
- 先设置临时路径，再导入捕获路径的模块；结束时关闭资源、恢复环境和删除拥有的临时文件。服务使用分配的端口，明确进程身份和退出确认；超时、启动或清理失败必须报错。
- 根 `test` 构建后依次执行 fast、integration、browser，分类入口按目录筛选。单独执行前完成初次构建，相关产物变化后重新构建。性能测量独立；不得擅自缩减默认范围、添加跳过、重试、额外运行器或门禁。
- `test:plan --base <ref>` 只输出范围；`test:affected --base <ref>` 自行构建并执行完整快速测试和按模块选中的集成、浏览器测试。核对累计差异、工作区新文件及删除/重命名两端，不用扩展名或 Bun `--changed` 代替模块规则。新模块、跨模块依赖和共享夹具调用方须同步维护选择规则及用例；未知归属回退全量，读取失败返回错误。
- CI 使用一份提交范围计划，每个平台构建一次，通过独立工作区执行串行类别和原生浏览器分片；核对实际执行文件并集及提交、代码树和平台身份。任务失败、取消、异常跳过或证据缺失不得放行；按范围结果不能充当发布所需的同树双平台全量证明。
- 页面测试读取当前构建产物，组件夹具使用已有 Vite 配置和私有缓存；文件内复用服务/浏览器，案例间隔离上下文，不跨文件共享可变资源。用真实响应、组件状态或布局完成条件替代准备阶段的固定等待，保留真实时间边界和代表性截图，关闭失败必须报错。
- 搬迁时核对源码路径、动态 URL、资源路径、发现规则、类型检查、构建、CI、Docker和文档。确认测试与夹具不进入发布产物，辅助目录与手动验收不被自动发现，不保留旧路径转发器。
