# 管理认证与访问控制使用指南

Bungee 是个人反向代理。基础功能是 Route、Service 和上游转发；管理入口默认匿名，代理路由默认公开。需要限制访问时，在插件中心分别启用“管理认证”和“访问控制”。两者独立，Route 与 Service 编辑器不配置认证。

## 初始化与升级

先执行 `bungee init`，再执行 `bungee start`。初始化只创建 SQLite 配置库，不生成凭证、不建立管理员。原生入口使用 `--initialize-config <配置库绝对路径>`。`BUNGEE_CONFIG_DB_PATH` 可指定配置库，初始化、启动和恢复必须使用同一路径。

升级前停止实例并备份配置库。v12 迁移移除当前配置中的旧全局／路由 `auth` 字段，保留历史配置快照，不转换旧 token；新配置写入不接受旧 `auth` 字段。升级后打开 Dashboard，按需启用管理认证和访问控制，在访问控制插件内重新创建 Key。

## 管理认证

插件 `local-accounts` 显示为“管理认证”。打开插件原有 switch，向导核对浏览器访问地址，首次建立一个管理员账号并确认密码；已存在管理员时验证该管理员。确认会话建立和发布结果后，管理入口使用账号会话。此功能没有成员、团队或角色设置。

密码为 6–64 个字符，服务端使用 Argon2id 摘要。浏览器通过 HttpOnly、SameSite Cookie 保存会话，HTTPS 使用 Secure；Cookie 写请求校验 Origin 和 CSRF。会话空闲 30 分钟或建立 8 小时后失效，改密会撤销管理员所有会话。

CLI 可向 `POST /api/auth/login` 发送 `{username,password,transport:"bearer"}` 获取短期 Bearer 会话，然后通过管理命令的 `--token` 使用；CLI 不自动保存会话。

停用管理认证需要当前有效管理员会话。切换完成后撤销会话并恢复匿名管理，管理员数据保留，重新启用时验证原管理员。已选择认证插件而插件故障或目录缺失时，管理入口拒绝访问，不自动恢复匿名；持久化的认证选择独立于当前插件目录。

## 访问控制与 Key

插件 `key-access` 显示为“访问控制”，设置页统一提供“API Key”和“路由访问”两个入口。

1. 创建 Key 时填写名称、可选到期时间及允许路由。新 Key 明文通过插件 SecretStore 加密保存，可在列表操作列点击“查看”后复制；旧 Key 只有摘要，无法还原明文。
2. 选择公开路由后，页面进入访问变更确认步骤，逐条列明“公开 → 需要 Key”。确认后保存 Key 授权并保护这些路由；返回修改不会写入数据。也可在“路由访问”中单独调整“是否公开”（打开为公开，关闭为需要 Key）。
3. 调用受保护路由时使用 `Authorization: Bearer <Key>`。缺少、过期、删除或无效的 Key 返回 401；有效 Key 越出授权范围返回 403。

路由保护集合与 Key 授权分开保存。删除最后一个 Key，路由仍受保护；只有显式解除保护才重新公开。允许路由 `null` 表示不限制，`[]` 表示拒绝此 Key 访问所有受保护路由。高级模型范围匹配最终上游模型，支持 * 匹配任意数量字符（例如 gpt-*），区分大小写；其他字符按字面匹配，无通配符时精确匹配；API 中模型 `null` 不限制，`[]` 拒绝全部，界面空白模型输入表示 `null`。

公开路由始终按匿名请求处理，即使请求携带 Key，也不消耗该 Key 的请求限速或 token 预算。Key 只用于代理访问；管理认证启用时，它不能代替管理员会话。

普通代理默认透传客户端的 `Authorization`，访问控制认证不会自动删除或改写该请求头。需要删除时配置 `headers.remove: ["Authorization"]`；需要使用独立的上游凭据时，通过 Route 或 Service 上游的 `headers.add`／`headers.replace` 明确设置。请求头改写发生在访问控制读取客户端凭据之后，不影响已识别的 Key 身份。托管上游（如 ChatGPT OAuth）遵循插件声明的凭据策略，由插件注入所选账号的凭据。

撤销发布确认后拒绝新请求；已经取得上游发送许可的请求继续完成。数据库保存成功不等于发布完成，页面会区分已保存、待发布和已生效；待发布或失败时应按提示刷新核验。创建后的后续授权或保护步骤失败，仍须先保存已显示的 Key 明文，再编辑该 Key 补完设置，不能把部分保存当作全部完成。

停用访问控制前，必须显式解除全部路由保护，并先停用依赖它的 Key 限速、Token 预算。策略和凭证保留。插件异常、未就绪或目录缺失时，持久化保护 guard 阻止受保护路由变为公开。

## 插件组合与开关

| 插件 | 效果与依赖 |
| --- | --- |
| `local-accounts`（管理认证） | 单管理员管理会话，与代理 Key 独立 |
| `key-access`（访问控制） | Key 生命周期、受保护路由集合、每 Key 路由与最终模型范围 |
| `key-rate-limit`（Key 请求限速） | 每 Key 的全实例速率和突发容量，依赖访问控制 |
| `token-budget`（Key Token 预算） | input + output 的累计或 UTC 自然月额度，依赖访问控制与计量 |
| `token-stats`（Token 统计） | 统计和估算费用，仅依赖计量，可用于公开路由 |
| `token-metering` | 全局计量服务，不能绑定 Route、Service 或上游 |

启用消费者时展示将自动开启的依赖，完整闭包一次性提交。保留原有 BSwitch 样式；依赖者仍启用或在途租约仍使用 provider 时，开关 disabled 并说明原因。停用消费者不自动关闭依赖。完整配置导入必须包含依赖闭包。

Key 限速或预算停用后，切换点之后的新请求取消对应限制，已接纳请求按原规则完成。停用保留策略和预算账本，重新开启不清零。停用后的策略只读，启用并就绪后可编辑。

## 预算与不完整计量

预算为每 Key 的正整数额度，消耗为规范化 input + output，缓存与 reasoning 分项不重复累加。预算耗尽返回 429，只阻止新请求；已接纳请求继续，最终用量可能超额。累计预算不自动重置，每月预算按 UTC 自然月，跨月流记接纳时的周期。模式变更不会重置累计与月份账本。

预算覆盖受保护路由上以该 Key 接纳的调用，不追溯计入公开请求、停用期间请求或无预算请求。实际发送并产生用量的失败及故障转移 attempt 也计入；内部故障转移不重复扣外部请求速率。

输入与输出分别优先采用官方 usage，缺失时采用带来源标记的估算，后续官方补全按差额修正。无法计量不计零：发送前已知不可计量返回 422；发送后观察丢失或账务未知时，流继续，受影响 Key 的新预算请求返回 503，直至恢复。新月份不会解除未知账务阻塞。

预算扩展提供计量来源、周期与待恢复 request/attempt 标识。统计失败只影响报表，页面显示统计可能不完整；预算使用独立耐久账本，不依赖统计队列或观测日志。统计不完整标记是持久标记，观测数据库自身不可写时只能记录错误，不能保证控制面收到该标记。

## 监听与反向代理

| 配置 | 用途 |
| --- | --- |
| `BUNGEE_MANAGEMENT_HOST` | 管理监听地址，默认本地；对外可设置为 `0.0.0.0` |
| `BUNGEE_MANAGEMENT_PORT` | 管理端口，默认 `8089` |
| `BUNGEE_PUBLIC_ORIGIN` | 浏览器访问的公开 HTTPS Origin；本地允许 loopback HTTP |
| `BUNGEE_TRUSTED_MANAGEMENT_PROXIES` | 可信代理精确 IP，逗号分隔；默认不信任转发头 |

对外部署使用 HTTPS 反向代理，管理入口是否要求登录由管理认证插件决定。可信代理必须覆盖 `X-Forwarded-For` 为一个有效客户端 IP；含多个地址的链不作为登录限速来源。未配置时使用实际连接来源，客户端伪造转发头无效。

## 本地离线恢复

停止整个实例，使用同一配置库和启动环境，然后执行 `bungee recover < recovery.json`；或将文件设为 `0600` 后执行 `bungee recover --file recovery.json`。输入上限 8192 字节，秘密通过 stdin 或文件输入。命令同时持 master 和 ingress 实例锁；master 崩溃但 ingress 仍运行时也拒绝恢复。自定义 `BUNGEE_INGRESS_INSTANCE_LOCK_PATH` 必须与启动时一致，建议绝对路径。

恢复管理员：

```json
{"kind":"identity","plugin":"local-accounts","payload":{"username":"admin","password":"替换为新的6至64字符密码","reason":"恢复管理访问"}}
```

已有管理员时必须指定原账号；无管理员时可建立一个。恢复撤销会话并保留审计，不自动开启管理认证，也不改变当前认证模式。

核验上游证据后，为一个待结算 attempt 补记输入／输出总数：

```json
{"kind":"plugin-state","plugin":"token-budget","payload":{"keyId":"KEY_ID","requestId":"REQUEST_ID","attemptId":"ATTEMPT_ID","inputTokens":100,"outputTokens":200,"reason":"已核验上游用量"}}
```

数量是该 attempt 的替换总数，按差额更新原周期和累计账本。相同补记幂等，不同内容重放拒绝，并保留状态及原因的审计。恢复停用插件状态不自动开启它；正常已结算 attempt 不允许人工改写。

普通配置导入／导出不包含 Key、管理员、会话或预算运行账本。物理整库备份包含这些数据，恢复时须核验备份时点的撤销和账务状态。

Key 操作统一为编辑／删除。编辑包含名称、有效期、路由与模型；删除移除凭证、授权与加密明文，已接纳请求继续，路由保护保持原状。“任意路由”包含后续新增路由的授权，不代表自动改变未来路由的公开状态。

访问控制列表操作为查看／编辑／删除。新建及编辑表单开启“任意路由”时隐藏具体路由选择，关闭后恢复原选择；操作按钮使用下一步／上一步／取消／保存，取消不提交变更。

受保护路由仍关联 API Key 时，不允许切换为公开，接口返回 409。关联包含指定路由和“任意路由”的授权；过期不解除关联。须先移除所有相关 Key 的路由授权或删除 Key。路由开关沿用带内置图标的 BSwitch，禁用原因在悬停提示中展示。
