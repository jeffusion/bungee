# 个人反代的管理认证与访问控制设计

Bungee 的核心是 Route、Service 和代理运行平台。管理入口默认匿名，数据面路由默认公开；管理员登录、Key 访问控制、Key 限速、Token 预算、计量与统计按需启用。使用步骤见 [认证指南](../guides/authentication.md)，平台契约见 [插件扩展架构](./plugins.md)。

## 范围与能力归属

| 能力 | 所有者 |
| --- | --- |
| Route、Service、上游转发与运行管理 | core |
| 管理认证接口、最终准入与持久化失败保护 | 通用 core Host |
| 单管理员账号、密码和 Cookie／Bearer 会话 | local-accounts，显示“管理认证” |
| Key 生成、元数据、过期、验证、撤销及路由保护 | key-access，显示“访问控制” |
| 每 Key 路由与最终模型授权 | key-access |
| 每 Key 全实例请求速率 | key-rate-limit，依赖 key-access |
| 每 Key 日、周、月或累计 Token／美元额度 | token-budget，依赖 key-access、token-metering 与 token-stats |
| token 规范化计量 | token-metering，全局服务 |
| 统计与费用估算 | token-stats，依赖 token-metering 与 models-dev |
| 插件 collection 与 resource extension 读取 | core 通用只读协议，数据由插件提供 |

产品面向个人反代，不提供多用户、团队、角色、公开注册或 SSO。Route 和 Service 编辑器只处理代理配置，没有认证字段。业务插件随发行版提供，默认不自动启用。

## 管理认证

未选认证 provider 时，管理 API 允许匿名管理；初始化只建库。开启 local-accounts 前建立或验证唯一管理员，证明候选会话可用，再提交认证选择并确认发布。已有管理员数据时验证原账号，不创建额外身份。

认证选择持久化并独立于目录 catalog；已选择的 provider 加载失败、未就绪或目录丢失时，管理入口返回不可用，不能自动恢复匿名。显式停用要求当前有效管理员会话，切换完成后恢复匿名管理、撤销会话并保留管理员数据。

账号使用 Argon2id，密码 6–64 个字符。会话只保存不透明摘要，默认空闲 30 分钟、绝对寿命 8 小时。浏览器使用 HttpOnly／SameSite Cookie，HTTPS 标记 Secure；Cookie 写请求校验公开 Origin 和 CSRF。CLI 登录可取得 Bearer 会话，CLI 不自动保存它。修改密码或恢复身份撤销会话。管理员拥有完整实例管理能力，没有成员或角色映射。

## 路由保护与 Key 授权

访问控制插件设置页统一维护 Key 和受保护路由。保护集合 `protectedRouteIds` 与每 Key 授权独立持久化、独立操作。创建、编辑或快捷关联 Key 不改变路由公开状态；“是否公开”开关只修改保护集合，已有 Key 授权也不阻止公开。

公开路由解析为匿名主体，即使携带有效、无效或已撤销 Key，也不消耗 Key 限速或预算。受保护路由要求插件验证的有效 Bearer Key；缺少或无效凭证为 401，授权越界为 403。Key 不能用于管理会话认证，管理员会话也不能代替数据面 Key。

Key 使用稳定 ID、名称、验证摘要、展示前缀、创建时间、可选到期时间与撤销状态。随机秘密至少 256 位，明文由插件 SecretStore 加密保存，授权的查看操作可读回；普通列表、配置导出与日志不暴露秘密。仅有摘要而无秘密存储记录时不能还原明文。Key 生命周期由 key-access 实现，core 不提供独立的凭证写接口。

每 Key 策略含 `routes` 和 `models`：`null` 不限制该维度，`[]` 拒绝该维度全部值，非空列表同维度为或、跨维度为且。界面模型空白输入表示不限制。路由引用稳定 ID，删除重建不继承授权。模型匹配变换后的最终目标，支持 * 通配符、区分大小写，无通配符时精确匹配，无法识别受限模型时拒绝；后续故障转移 attempt 仍检查原请求策略。

删除最后一个 Key 不解除任何路由保护。只有显式移除全部保护集合，并满足依赖约束后，才允许停用访问控制。持久 guard 保存保护要求；插件崩溃、目录缺失、状态读取失败或发布未就绪，均不能把已有受保护路由变为公开。

撤销与最终上游发送许可在 ingress 同一序列排序。发布确认后的新请求拒绝，已经取得许可的流继续；连接建立、body 读取不算已接纳，keep-alive 下一请求与客户端重试属于新请求。保存但未发布的结果必须明确显示，不能报告即时生效。

## 可选限制的停用与依赖

Key 限速和预算可显式停用，配置、凭证和账本保留。准入切换后的新请求取消对应限制，旧请求继续按原快照与租约处理；未取得许可的准备项取消并按新代际复核。待结算记录决定旧实例排空时间，不将数据库提交当成运行切换完成。

依赖闭包一次性启用：Key 限速依赖访问控制，预算依赖访问控制与计量，统计依赖计量和目录。被启用消费者或在途租约依赖的 provider 不能关闭。停用消费者不自动关闭依赖。访问控制另有“保护集合必须为空”的业务 guard，导入及完整配置写入执行相同检查。

## key-rate-limit 插件

此插件依赖 key-access；仅对受保护路由上的数据面 Key 请求生效。启用后可为每 Key 配置每秒请求数及突发容量，无策略的 Key 不额外限速。Key 桶在 ingress 按 Key ID 全实例共享，不随 worker 数量或路由倍增；现有路由限速同时生效。

只对通过最终外部请求准入的一次调用计数，内部故障转移不重复扣减。插件向 Host 返回无 I/O 的内存状态计划，Host 在 ingress 同一共同决定中发布速率更新及发送许可；其他校验或准备拒绝不产生速率扣减。许可响应丢失按 request ID 查询，不重复扣减；许可已发放后客户端取消仍算已接纳调用。达到速率返回 429 和 Retry-After。ingress 重启按突发容量重建桶，不承诺速率桶耐久保存。

存在有效速率策略时也可直接停用，切换后新请求不扣该插件的桶，持久化策略保留。瞬态桶不承诺耐久保存，实例重建仍按突发容量初始化；重新启用不改变其他插件或现有路由限速的计数。基础层不内置每 Key 桶策略。

## token-metering 与 token-stats

token-metering 在插件中心显示，是 global 服务插件，不能绑定 route/service/upstream。单独激活只提供服务，没有消费者时不读取请求用于 token 解析、不写账本、不展示统计或拒绝请求。

token-stats 依赖 token-metering 并订阅计量结果。它提供统计和价格展示；其队列满或失败可丢弃报表记录，但必须标记统计不完整，不影响基础代理。budget 与 stats 同时开启时共享每个 attempt 的解析过程，预算不查询 token-stats 的数据库或队列。

计量服务输出规范化 input/output、cache 分项、计量来源及完整性。不同消费者各自持有数据；没有“跨插件直接读 storage”接口。插件依赖自动激活、禁止停用、版本校验和服务就绪由平台统一保证。

## token-budget 插件

### 启用效果和额度

启用 token-budget 自动启用 key-access、token-metering、token-stats 及其目录依赖。预算复用定价服务，但不依赖报表队列。没有预算策略的 Key 不受额度限制；存在策略时，预算覆盖该 Key 在受保护路由上的调用，不由 route/service 的插件绑定决定。仍要求该请求可计量，未知协议不能当作免费流量。

预算支持 daily、weekly、monthly、cumulative 四种模式，以及 tokens、usd 两种单位。Token 额度为正安全整数；美元额度最多六位小数，账本使用整数 nanoUSD（1 USD = 10^9 nanoUSD）。Token 消耗为规范化 input + output，缓存和 reasoning 不重复相加。日/月按 UTC 日历，周从 UTC 周一开始。

接纳时固定策略与 day/week/month，迟到结算仍记原周期。启用期间同时记录累计、日、周、月账本，切换模式或单位不清零；无预算期间不追溯。Token 与金额 unknown 分别阻止对应单位的准入。不可定价不能视为免费，详细契约见[预算集成](../../plugins/token-budget/INTEGRATION.md)。

额度耗尽拒绝新请求，已有请求继续，不预留最大输出。例如已用 9900、额度 10000，同时放行两个各用 200 的请求，最终可能到 10300。周期切换不解除未知账务阻塞。

### 可靠计量与账本

预算通过 token-metering 的必需服务订阅得到结果，使用自己的 durable-state 账本，不依赖统计是否开启或日志是否清理。所有实际发送且消耗 token 的 attempt 都计入同一请求的 Key，包括失败和故障转移；未发送的 attempt 不计。

输入和输出各自优先采用官方 usage；缺字段时接受可用的本地估算，界面分别显示官方/估算来源和完整性。后续官方补全替换对应估算，只更新差额。累计流式 usage 不重复相加。正常取消/中断计入已观察 token，并标记 partial；不假装知道上游在取消后继续生成的用量。

无法计量也无法估算时不能当零。发送前已知协议或内容不可计量则拒绝该预算请求，返回 422；发送后观察丢失、估算截断、不可计量多模态或无法结算时，已发送流继续，预算启用状态下相关 Key 的新预算请求返回 503。完整官方 usage 可以覆盖此前观察丢失。恢复先重放记录，无法恢复时通过受控本地运维补记并留痕，不提供在线人工账务编辑页面。明确停用后这些状态不限制新请求，但保留证据，重新启用时仍须恢复受影响 Key 的账务。

首次准入持久化请求快照；每个预算 attempt 发送前另外持久化待结算记录。Key、request、attempt、周期及结算版本绑定，重放不重复计数；不知道持久化结果时先查询，不换 ID 重新发送。ingress 的预算插件先反映已知消耗，再确认 master 持久化；结果不确定则阻止该 Key 新预算准入。

master 故障时已经发送的流继续，但尚未登记的新预算 attempt 不发送，包括已接纳请求的内部故障转移；按原请求超时/失败机制结束，不无限等待。冷恢复缺少证据不将账本置零。新月不能解除尚未恢复的账务阻塞。

### 停用

存在有效预算策略、在途预算请求或待结算记录时也可直接关闭 token-budget。准入切换后新请求不受预算限制且不计入预算账本；原请求继续按原快照计量、结算，包括必要的后续 attempt 准备。撤销的 Key 不再可调用，但它的在途账务仍须完成。停用不绕过 master 故障时尚未登记 attempt 不能发送的规则。

停用保留策略与累计、日、周、月账本，重新启用沿用；停用期间的请求不追溯计入。旧实例及计量租约保留到在途处理和结算恢复完成，无法结算时可保持排空/待恢复状态，不阻止停用后的新请求。排空期间重新启用使用新代际和同一幂等账本，不能重复结算或清零；受影响 Key 在恢复前拒绝新预算准入。token-metering 若仍被消费者依赖或旧预算租约引用不能关闭。统计报表写入失败与预算结算分别处理；预算仍启用时不能停用其定价 provider，计量故障不能变成默认允许。

## 界面与通用资源

插件中心保留现有 BSwitch。依赖或 guard 不允许停用时开关 disabled，并给出依赖者、在途租约或未解除路由保护的原因；不改变基础组件样式。

访问控制设置页包含 API Key 与路由访问，创建 Key 默认选择指定路由；保存授权保持路由公开状态不变。高级模型、请求限速和 Token 预算按各插件能力呈现。停用扩展可通过通用只读资源协议查看保留配置，启用并 ready 后才可修改。管理认证只提供单管理员的启用、登录、改密、退出和停用交接。

core 不解释插件策略、账号表或额度字段；collection 和 extension DTO 读取只授予 `get/list`，不启动停用插件，也不授予写能力。Key 创建与撤销由访问控制插件 API 执行。

## 部署、导入与恢复

管理默认监听本地，可通过启动环境配置对外监听。对外使用 HTTPS 反向代理并配置公开 Origin、可信代理；内部 RPC 只监听 loopback。初始化原生参数为 `--initialize-config`；全局及 Route 配置不接受 `auth` 字段。

普通配置导入／导出不替换 Key、管理员、会话或预算运行账本。涉及激活集合、认证选择或保护对象时，同样检查当前管理身份、完整依赖闭包、持久 guard 和认证切换证明。离线恢复只支持 `identity` 与 `plugin-state`，要求整个实例停止并持 master／ingress 锁，身份恢复不改变激活模式。

物理整库备份包含运行状态。恢复必须核验备份时点的会话、Key 删除和预算账务，旧备份不能证明当前状态。


管理认证 control 与数据面发布分别就绪；发布失败和恢复 stopped 不会停止已就绪 provider。具体健康和存储边界见[生命周期](storage.md)。
