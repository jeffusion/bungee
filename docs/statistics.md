# 请求统计口径

仪表盘通过 `GET /api/stats/dashboard?range=1h|12h|24h` 读取数据。一次响应中的趋势和上游统计来自同一时间窗口、同一个 SQLite 只读事务；时间范围为 `[startTime, endTime)`。

## 最终结果

所有统计共用以下分类规则，按顺序判断：

1. `protocol_outcome = failed/incomplete/cancelled`、`success = 0` 或 HTTP 状态码大于等于 400：失败。
2. 其他记录：成功，兼容没有协议结果字段的历史日志。

统计只区分成功和失败，成功数加失败数等于总数，失败率等于 `100% - 成功率`。没有请求的时间段展示成功率 100%、失败率 0%。

失败原因保留原始日志值：Bungee 请求超时记录为 `protocol_outcome = failed`、`protocol_code = request_timeout`；`cancelled` 表示请求提前中断，不能仅凭该值判定为上游超时。统计将中断归入失败，但不改写原因，也不将已经收到协议完成事件的请求因后续客户端断开而改判为失败。

## 计数单位

- **客户端总览与趋势**：按请求链计数，一次客户端请求即使发生重试也只计一次。使用最终尝试的结果，按请求链第一条日志的时间归桶；耗时包含重试间隔。
- **上游统计**：每次上游尝试单独计数，按该条日志的时间计入窗口。上游请求分布包含成功和失败，流量占比的分母是全部上游尝试。
- **没有上游的请求**：例如鉴权失败或直接响应，只进入客户端统计。

例如一次请求第一次访问上游 A 返回 503，重试上游 B 成功：客户端总览增加一次成功，上游统计增加两次尝试，其中一次失败。两个维度的数量有意不同；API 的 `units` 字段及页面说明标明各自单位。

仪表盘保留所有上游，避免各面板分别截取前十名后出现遗漏。独立上游接口仍保留原有默认数量限制。

## HTTP 状态码与协议结果

流式响应可能先返回 HTTP 200，然后发生协议错误、超时或取消。HTTP 状态码保留真实值，不能在流结束后改成 500。

状态码面板明确标为 HTTP 状态码，作为辅助信息，同时显示成功、失败结果。`failed2xx` 表示 HTTP 2xx 后仍失败的尝试，是 2xx 中的子集，不是额外请求。

各上游的成功率、失败率以该上游的全部尝试为分母；流量占比以全部上游的尝试为分母。成功／失败筛选接口只改变分布的 `count` 和 `percentage`，不改变该上游的完整结果计数及失败率。

本次调整直接使用已有日志字段，不修改 HTTP 状态码，不新增数据库迁移，也不影响转发、响应大小限制或超时配置。
